When the plugin's `openrevive` MCP server is available, use its direct tools: `list_targets`, `get_status`, `get_ui_tree`, `find_ui`, `act_ui`, `get_screenshot`. Read [MCP control](references/mcp.md) for tools, setup, bounded results, cancellation and freshness. Each tree returns a session-local single-use `snapshotId` valid for 30 seconds. Find a unique node locally, act once, then verify a fresh tree/image or independent receipt. Prefer this to shuttling snapshot files through shell commands. Both Mac and iPhone tools refer to the remote test hardware, not the modern controller.

For OpenRevive 0.8, prefer `ui_observe`, `ui_perform` and bounded `ui_workflow` scenarios with exact selectors and explicit postconditions. Independent MCP/CLI clients share a persistent supervisor. Reserve important operation IDs; query cancellation/uncertain outcomes instead of replaying input. Read [shared device sessions](references/device-sessions.md) for ownership, durable recovery, handover, web document contexts, diagnostics and the JSON-lines CLI. Native input guards remain authoritative.

The self-contained CLI at `scripts/openrevive.py` remains available for setup and builds. It uses Python 3.9+ on the controlling machine and the old Mac's built-in Python 2.7 plus Xcode. The optional MCP server additionally needs controller-side Node.js 20+; no package manager, MCP server or modern runtime is needed on Lion. Physical iPhone operations additionally use controller-side libimobiledevice/libplist and ideviceinstaller; VNC password authentication needs the Python package `cryptography` in this same Python. See [iPhone setup and control](references/iphone.md).

Set `OR` below to the absolute path of this skill's `scripts/openrevive.py`. Invoke it with `python3 "$OR" ...`. In the source repository, `./bin/openrevive` is the same entry point. Resolve the actual installed skill path; do not assume a plugin cache location.

## Start with real state

1. Run `python3 "$OR" doctor`. JSON lists each missing capability and its remedy; warnings about an absent iPhone/signing do not prevent desktop use. A failed SSH connection is an error, never evidence that the Mac is dead.
2. If no host profile exists, follow [setup](references/setup.md). Configuration precedence is `--config`, `OPENREVIVE_CONFIG`, nearest `.openrevive/hosts.json` up to the repository root, then `~/.config/openrevive/hosts.json`. Global `--host NAME` chooses a profile; default is `blacklion`. Never put a password in the profile or commit private keys.
3. If the helper is missing or outdated, run `bootstrap`. The offline payload installs under its dedicated remote root and atomically changes `current`; `rollback` restores `previous`. Repeat installation is supported. Do not overwrite unrelated projects or change global SSH policy.
4. If accessibility is disabled, use the exact remedy in doctor or [troubleshooting](references/troubleshooting.md). Already authorized setup can use `repair accessibility --prompt` or a temporary `--password-env VARIABLE`; plain `repair accessibility` tries cached `sudo -n`. It only applies Lion's global marker on 10.7.3-10.8.x. Restart affected target apps after enabling. Ordinary GUI work needs no root.

## Operate the desktop

1. Inspect `ui status`, `ui apps`, `ui windows`, and `ui screenshot /absolute/output.png`. Capture wakes the display first: Lion otherwise returns stale pixels after display sleep. View the resulting image before choosing coordinates.
2. Resolve a current PID from `ui apps`. Prefer `ui tree PID --depth 6 --limit 500` and semantic `ui set` / `ui action` over coordinates. Scope the tree to the intended window. Increase bounds only when needed; `truncated: true` means incomplete coverage.
3. For AX changes, pass the fresh node's `path`, `role`, `title` (including an empty title), and owning `bundleId`. Example: `ui set PID PATH 'text' --role AXTextField --title '' --bundle APP_ID`; press with `ui action PID PATH AXPress --role AXButton --title 'Apply' --bundle APP_ID`. A changed role/title/owner is a failure; reread the tree rather than bypassing the guard. Paths are ephemeral, not stable IDs; identical sibling fields can still require window/frame/description verification.
4. If AX is unavailable, use a fresh screenshot and `ui focus PID`, `ui click X Y`, `ui double-click X Y`, `ui move X Y`, `ui drag X1 Y1 X2 Y2`, `ui scroll VERTICAL [HORIZONTAL]`, `ui type 'Unicode text' --pid PID`, and `ui key a --modifiers cmd`. Coordinates start at the main screen's top-left. Positive vertical scroll is up. Named keys include return, tab, escape, arrows; numeric virtual key codes also work. Unicode input preserves the clipboard.
5. Verify every meaningful action through a new tree, screenshot, app log or independent receipt. A `posted; verify UI` response only confirms event delivery. Use `ui probe` and `ui probe-result` for a disposable Cocoa loop before changing an unfamiliar app. Avoid locked/login screens and unattended destructive actions outside the user's scope.

## Deploy, build and collect results

- `sync LOCAL_DIR REMOTE_DIR` incrementally uploads source without remote deletion. `.git/` and `.DS_Store` are excluded. Add `--exclude build/` as needed. `pull REMOTE_FILE LOCAL_FILE` retrieves logs or binary artifacts atomically.
- `exec --cwd REMOTE_DIR --timeout 120 -- PROGRAM ARG...` preserves argv and exit status. `--env KEY=VALUE` passes explicit environment entries. An intentional shell requires `/bin/sh -c '...'`; otherwise avoid shell quoting entirely.
- `aqua ... -- PROGRAM ARG...` runs via a temporary per-user Aqua LaunchAgent and cleans it up. Use it for old Simulator-dependent tools; SSH runs in the Background bootstrap context. It needs the SSH user logged into the desktop. Timeout exits 124 and stops the command group. See [workflows](references/workflows.md).
- `xcode sdks`, `xcode list REMOTE.xcodeproj`, and `xcode build REMOTE.xcodeproj --sdk iphonesimulator6.1` use installed Xcode. Use explicit SDK/architecture/settings. `--unsigned` is for build diagnostics; a compiled device bundle is not proof of installation or launch.
- `sim build-probe`, then `sim launch REMOTE.app --sdk 6.1` use bundled **ios-sim 1.7**, built with GC support for Xcode 4.6. Simulator logs are under `REMOTE_ROOT/work/logs/`. Check the actual app process, pixels and receipt. Mac AX does not expose UIKit's simulator tree on this host.
- `usb list` compares physical USB with usbmuxd. If physical USB sees a phone but mux does not, unlock it; a still-stuck Lion daemon can be restarted with `usb repair --prompt` or an authorized temporary `--password-env VARIABLE`. Read the list again. Never infer absence from mux alone or reuse historical UDIDs.

## Operate a physical iPhone or iPad

For first-generation iPad / iOS 5.1.1, read [the device-specific workflow](references/ipad.md). Its native screen is 768x1024 and its GraphicsServices touch path differs from iOS 6; Veency keyboard input is unverified and failed the live probe. Use UIKit edits.

Read [the device workflow](references/iphone.md) before first setup. Pass the exact current `device --udid UDID` on every call. Each device command owns a temporary SSH tunnel and local pairing bridge; the old daemon cannot store modern pairing metadata itself. `device pair` must pass a subsequent validation, then `device info` must read the actual identity and iOS. Pairing secrets stay in private local files.

- `device --udid UDID build-probe /absolute/output-dir` builds armv7 with old Xcode and pulls an IPA. `install /absolute/app.ipa` verifies the actual installer result. Stock devices need valid signing/provisioning; the demonstrated unsigned route uses the phone's **existing** jailbreak and AppSync.
- `prepare` mounts a matching DeveloperDiskImage from the user's remote Xcode. `screenshot /absolute/phone.png` uses the real screenshot service. Images are never bundled or downloaded from an unofficial source. On iOS 6, LookupImage can falsely report no image despite an active /Developer mount; the toolkit checks the real screenshot service before mounting again.
- For the optional existing-jailbreak route, `bootstrap-control --restart` adds one USB-only paired lockdown service and requests a normal phone restart. Wait and unlock once, then rerun `bootstrap-control` without the flag. This compiles/signs a small native helper and proves UID 0. Do not repeatedly pass `--restart` to a working device. The original Services plist is backed up; setup never jailbreaks or restores firmware.
- `launch BUNDLE_ID` invokes SpringBoard's legacy launch API. Confirm `state` reports the same `frontmostBundleId`, then capture the actual app. AppSync installation can succeed while `idevicedebug` fails to get its task; that error is not launch proof.
- `setup-vnc --respring` installs nine pinned, hashed official repository packages and configures a random 8-character Veency password. It restarts the UI to load the extensions. Veency also listens on the phone's LAN; the toolkit connects through USB/SSH and requires password authentication. Subsequent calls normally need neither setup command.
- `screenshot --vnc /absolute/phone.png` works without a developer image. Inspect it before `tap X Y` or `swipe X1 Y1 X2 Y2`; coordinates are **framebuffer pixels**, 640×960 on this iPhone 4, not UIKit points. `type TEXT`, `key return`, `home`, and `lock` send real device input. Home wakes a sleeping screen. For a passcode-free iOS 6 lock screen, inspect a fresh frame then drag the actual slider. Never treat a black frame as a successful app screenshot or attempt passcode guessing.
- `exec --timeout 30 -- PROGRAM ARG...` runs as root through the paired USB service, preserving argv, output and exit status. Its native timeout stops the process group. `pull /device/file /absolute/local/file` retrieves files through existing AFC2. Scope commands to this test device and use an intentional `/bin/bash -c` only when needed.
- For app structure and concurrent input, read [UIKit and multitouch](references/uikit.md). On the verified existing jailbreak, `setup-uikit --respring` compiles and installs the native bridges; wake/unlock afterwards. Repeat plain `setup-uikit` checks hashes and the loaded HID build without restarting an intact installation. `ui-status --bundle APP_ID` checks current endpoints.
- Prefer [unified UI discovery and routing](references/unified-ui.md) when the screen owner is uncertain or overlays may exist. `ui-processes` discovers current UIKit endpoints; `tree --all --output /absolute/interface.json --summary` saves real process/window trees and prints compact coverage. `ui-find FILE --label TITLE --role button [--owner BUNDLE]` selects a unique actionable target; `ui-action FILE NODE auto` chooses semantic app input, native SpringBoard/HID, or AssistiveTouch VNC. Read a new tree and verify the result after every action. Covered, inactive, ambiguous, unknown-route and stale targets fail; do not bypass the guard with old coordinates.
- `tree --bundle APP_ID --depth 12 --limit 800 --output /absolute/tree.json` reads actual UIKit views and accessibility-container elements. Select a unique visible node by label, class, role and bounds. `ui-action /absolute/tree.json NODE_ID set-text -- 'Привет 日本語'` focuses the field and replaces its selected document through UIKit keyboard input; the app owns validation and change callbacks. The field stays in editing mode. Read a fresh tree, then use its advertised `end-editing` action to resign first responder and let the app commit. Verify saved state by reopening the form or reading an independent receipt; displayed text alone proves only the edit. `isFirstResponder` reports focus without exposing secure text. `press`, `tap` and `scroll '[0,100]'` retain owner/PID/session/snapshot/identity/geometry guards. **Read a new tree after every action attempt**, including rejected edits: focus or selection may already have changed. Snapshots expire after 30 seconds, are superseded by another tree and consumed by actions. Secure field values/subtrees are redacted. More actions and scroll ranges are described in the reference.
- `pinch X Y START_SPAN END_SPAN --bundle APP_ID --duration 1` and `gesture /absolute/tracks.json --bundle APP_ID` deliver real concurrent HID contacts, up to five fingers with independent timed paths. Positions and spans use physical pixels; `scroll` offsets use UIKit points. Playback checks unlocked foreground owner/PID each frame and releases contacts on interruption. `maxContactsSent` proves dispatch; verify app events or visible results.
- For Home, the switcher, notifications and system dialogs, read [SpringBoard/system control](references/system.md). `system-state` discovers actual ownership; `tree --system --output /absolute/system.json` reads internal windows and labelled icons. Use `ui-action` on that fresh system snapshot, `system-control SNAPSHOT switcher|notifications|dismiss-switcher|dismiss-notifications`, or `gesture FILE --system-snapshot SNAPSHOT`. System input checks the captured foreground/PID/lock/overlay context; re-read after every action. Home has an empty foreground bundle, and icon page -1 is Spotlight. AssistiveTouch is included by `tree --all` and automatic actions select its verified VNC route; it did not react to native HID. Use the unified reference to find its real menu buttons instead of maintaining coordinates.
- Verify a form action using a fresh screen plus an independent app receipt. The probe writes `Documents/probe-result.json`; use a fresh tree's `containerPath` or a current `find`, then `pull`. Its `Documents/multitouch-result.json` records real UIEvent touches and pinch recognizer results; `Reset touches` resets it. Use a new text nonce so an old receipt cannot pass.

`usb tunnel` remains available for external libimobiledevice tools, with `USBMUXD_SOCKET_ADDRESS=127.0.0.1:27015`, and includes the same local pairing bridge. Stop it after use. Control is serialized per phone; overlapping root or UIKit operations fail instead of overwriting commands. Do not operate the phone concurrently from another controller. UIKit/HID is verified on iPhone3,1 / iOS 6.1.3 in portrait. The unified tree preserves each process owner and explicitly reports unbridged candidates; it does not invent UI trees for headless/non-UIKit daemons. Custom canvas/OpenGL content, web DOM and unknown overlay owners need screenshots or explicit support. Scroll and re-read virtualized lists. Other hardware, iOS generations and landscape need live validation.

## Known limits and repairs

Read [capture freshness](references/capture.md) when Veency repeats old pixels. A new VNC connection can initially return a cached surface: the client warms up for two seconds and issues another full-frame request, with an eight-second capture deadline. Capture receipt time is not a device frame timestamp. If pixels disagree with a fresh UI tree, do not act on those coordinates or respring the phone as a routine repair.

Read [troubleshooting](references/troubleshooting.md) for misleading AppleScript authorization errors, AX failures after enablement, stale frames, Xcode paths, garbage collection, simulator launch, and USB gaps. Verified baseline: MacBook4,1 / OS X 10.7.5 / Xcode 4.6.3 / iOS SDK 6.1, one 1280×800 screen. Other 10.7.3-10.8.x hosts are intended targets requiring a live doctor and probe pass.

Instruments UIAutomation currently fails authorization/session setup on BlackLion. Its exit code can be zero on failure. Do not report an Automation test as passed without its own success marker, verified receipt and absence of failure logs. Do not weaken `/etc/authorization` to work around it. Desktop AX and the physical UIKit/HID bridge work independently of Instruments; Simulator UIKit extraction remains unverified.

When extending the toolkit, keep the remote side compatible with Python 2.7/Xcode 4.6, preserve return codes and argument boundaries, update the relevant reference, and rerun the affected package/live checks in the source repository. Report demonstrated capabilities separately from remaining hardware or authorization limits.
