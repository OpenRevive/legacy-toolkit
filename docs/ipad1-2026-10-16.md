# iPad 1: физический прогон OpenRevive, VK и DNS/CA

Проверка 16 октября 2026 года, Asia/Tokyo. **iPad1,1, iOS 5.1.1 (9B206), armv7**, USB через BlackLion / OS X 10.7.5 / Xcode 4.6.3. UDID `7de8488b450394ab6417308beffa23e8c2f95f14`. Одновременно подключённый iPhone выбирался только для контрольного чтения состояния.

Это аудит работающего стенда с исправлениями для iPad. Ниже отдельно указаны успешные проверки, измеренные отказы и непроверенные возможности. Он не означает, что все исторические клиенты VK или все их функции поддерживаются.

## Что добавлено и исправлено

- Профиль iPad 1 / iOS 5.1.1, размеры 768×1024 и отдельная сборка нативных мостов под iOS 5.0. iPhone сохраняет профиль 640×960 / iOS 6.
- Настоящие события GraphicsServices из SpringBoard для iOS 5. Прежний IOHID callback остаётся для iOS 6. На iPad подтверждены реальные UITouch и UIPinchGestureRecognizer, а не только ответ об отправке.
- Поиск DeveloperDiskImage также в каталоге Xcode `5.1/` без суффикса build; подпись тестовых приложений через `codesign_allocate` из самого Xcode.
- PreferenceLoader добавлен в девять закреплённых по версии и SHA-256 пакетов Veency. На iOS 5 перезапускается SpringBoard.
- TouchProbe и DNSProbe собираются для iPhone/iPad и запускаются на iOS 5. У DNSProbe убраны вызовы Foundation subscripting, отсутствующие в этой системе.
- Защищённая удалённая разблокировка устройства без пароля, обнаружение Notification Center на iOS 5, клавиша Return через настоящий UIKit keyboard pipeline.
- Автоматические тапы и unified input отказывают при несовпадении виртуального экрана приложения и физического экрана. Проверка не позволяет отправить координаты 320×480 как пиксели iPad.

Применены существующие jailbreak, AppSync и AFC2. Прошивка не восстанавливалась, новый jailbreak не устанавливался. Подготовка добавила выделенный USB root helper с резервной копией Services.plist, Veency и нативные мосты.

Проверка MCP: 37 публичных вызовов; установленный пакет также проверен из `/tmp`. Неудачная отдельная копия VK 1.0 после опыта удалена.

**Veency keyboard:** исходный RFB прогон не сохранил текст в сфокусированном поле. Нативный UIKit ввод с тем же контрольным текстом прошёл. VNC dispatch нельзя считать доказательством набора. Итоговый повтор с предварительно очищенным полем сохранён в [acceptance.json](ipad1-evidence/acceptance.json).

**Режим iPhone:** VK 1.1 и IAmRich используют виртуальный экран **320×480**. Для VK проверялись физические координаты по свежему снимку и отдельной калибровке окна 1x. Это не универсальная автоматическая карта для режимов 1x/2x. Автоматический node tap и unified input в таком пространстве намеренно заблокированы. Нативные iPad приложения работают через обычный маршрут.

## DNS и CA

DNSProbe на реальном iPad выполнил DNS UDP/TCP, HTTP и HTTPS 200 для `hello.openrevive.test` (UpCloud) и `vscale.openrevive.test` (VScale). TLS — **1.2**. Правильный anchor принят; неизвестный CA и неверное имя отвергнуты. Оба HTML-документа отображены в UIWebView. Уникальный run присутствует в независимых nginx-журналах обоих origins. Сам этот probe использует явные app anchors и не меняет системное доверие.

Дополнительно выполнен обычный пользовательский маршрут:

1. Safari скачал публичный `OpenRevive Lab CA` по HTTP. Публичный сертификат побайтно совпал с локальным DER; SHA-256 `a433e9548b6628e0aecbf09378019ed231337949c20f00510aeaa25597fe6923`.
2. Профиль установлен через Settings, получен экран **Profile Installed**.
3. Safari открыл `https://vscale.openrevive.test/` с закрытым замком и содержимым VScale. Независимый журнал содержит уникальный query, HTTP 200 и `iPad; CPU OS 5_1_1`.
4. После проверки профиль удалён. Прежние **DigiCert Global Root G2** и **ISRG Root X1** сохранены. Временная вкладка закрыта, исходная вкладка восстановлена.

Публичный профиль содержит root v2 для VScale/CT127; старый `hello` подписан отдельным root v1 и проверялся через app anchor. Системное доверие Safari к `hello` не заявляется. Проверка Safari после удаления CA на новой TLS-сессии не выполнялась; отрицательные trust-проверки выше сделаны нативным probe.

**CT127** (`192.168.0.129:443`) из текущей Wi‑Fi сети не достигнут: отдельный armv7 TCP probe завершился с `ETIMEDOUT` через 6 секунд. Положительный контроль `45.8.249.60:443` подключился. Это ограничение доступа к домашней LAN; HTTPS CT127 на этом iPad не подтверждён.

Временный DNS `213.163.200.236` был нужен для VK и Safari. Восстановлены обе прежние записи активной Wi‑Fi службы: `192.168.11.1` и `2404:7a81:39e3:3600::1`. Persistent Wi‑Fi preferences и DNS/CA обоих Mac не менялись.

## VK и остальные приложения

| Объект | Проверка и граница результата |
| --- | --- |
| Оригинальный `com.vk.VKApp` 1.1 | Установка, запуск, synthetic login, newsfeed, friends, online filter, собственный и чужой profile |
| Переписка VK 1.1 | iPad отправил сообщение **10006**, получил **10007** через long poll без UI-действий после API trigger; оба текста и read state подтверждены SQLite и wire receipts |
| Оригинальность executable | SHA-256 установленного VK 1.1 совпадает с executable исходного IPA; код клиента не патчился |
| VK 1.0 | Отдельная копия `org.openrevive.vk10.ipad1` установилась, но не осталась запущенной. Исходный executable зашифрован; точная причина завершения этим опытом не установлена. Работоспособность не заявляется |
| Установленные пользовательские VK 2.0 и DrKLO | Не заменялись и не авторизовывались; прежние приложения проверены по итоговой инвентаризации |
| `io.ozio.IAmRich` | Имеющееся приложение запущено, его реальный экран и UIKit tree получены; отдельный экран совместимости iPhone |
| Архив IPA | Инвентаризировано **67** файлов, включая один quarantine. У 41 MinimumOSVersion не выше 5.1.1, у 26 выше; это только метаданные, не доказательство запуска или backend-совместимости |

В тесте использовались исключительно лабораторные аккаунты `openrevive-vk11` и `openrevive-anna`. Подключения к настоящему VK и реальным пользовательским перепискам не было. Клиентский User-Agent содержит `VKontakte 1.1 (iPad; iPhone OS 5.1.1; ja_JP)`; long poll — CFNetwork 548.1.4.

Японская candidate bar перекрывает toolbar переписки этого старого клиента. Смена на English и повторное открытие диалога позволили отправить сообщение. После теста возвращена исходная Japanese Kana. Отказ ввода в перекрытое поле был корректным. Изменение раскладки при уже открытом диалоге также нарушает его layout; код клиента не исправлялся.

Backend build при опыте — `a8a8e7893425`. Выполнены отдельные локальные HTTP/SQLite проверки всех **46** каталогизированных методов, 10 execute templates, девяти типов вложений, сообщений/long poll, фото, walls, people API и сохранения после перезапуска тестового сервера. Серверные тесты не подменяют физическую проверку всех UI-переходов. Upload из фототеки iPad, playback audio/video, все действия стены и фото, APNS, остальные версии/сторонние клиенты не прошли полный физический прогон. Общий lab-сервис в этом опыте не развёртывался и не перезапускался.

После возврата DNS VK вновь не имеет маршрута к synthetic backend — это ожидаемый результат отката тестовых сетевых настроек.

## Воспроизведение и доказательства

[Сводка и ограничения](ipad1-evidence/acceptance.json), [хеши файлов](ipad1-evidence/manifest.json), [порядок работы с iPad](../plugins/openrevive/skills/legacy-mac/references/ipad.md).

Из корня репозитория, с актуальным UDID:

```sh
python3 tests/check_ipad_live.py identity --udid ACTUAL_UDID
python3 tests/check_ipad_live.py basic --udid ACTUAL_UDID
python3 tests/check_ipad_live.py uikit --udid ACTUAL_UDID
python3 tests/check_ipad_live.py gestures --udid ACTUAL_UDID
python3 tests/check_ipad_live.py system --udid ACTUAL_UDID
python3 tests/check_ipad_live.py compatibility --udid ACTUAL_UDID
node tests/check_ipad_mcp.mjs --udid ACTUAL_UDID
python3 tests/verify_ipad_evidence.py
```

Сетевые проверки требуют подготовленных сертификатов/config и разрешения текущей сети на DNS. `tests/check_ipad_network.py vk_restore --udid ACTUAL_UDID` возвращает сохранённые адреса только при совпадении UDID, Wi‑Fi service и gateway. Pairing-записи, пароли, ключи CA, bearer credentials и IPA в публичные доказательства не включены.

Протокольные и packaging регрессии выполнены после изменений. Исходники и установленный пакет сверены; для подхвата обновлённого каталога MCP может требоваться новый чат или перезагрузка плагинов. Итоговые результаты относятся к portrait; landscape и AssistiveTouch на iPad не подтверждены.

Закрыты **10 из 10 пунктов аудита**, незакрытых и отменённых — 0. Эти пункты требуют измерить и классифицировать результат; обнаруженные отказы не превращены в успешные функциональные проверки.
