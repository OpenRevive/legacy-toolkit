# OpenRevive 0.6: прямые MCP-инструменты

MCP-сервер входит в плагин и работает на современном Mac. Он использует существующие SSH/USB-мосты для BlackLion и iPhone 4. Node.js 20+ и Python 3.9+ нужны только на контроллере. Нативные помощники на Lion и iOS остаются версии 0.5; обновление интерфейса MCP не требует respring телефона.

## Инструменты

| Инструмент | Возможность |
| --- | --- |
| `list_targets` | Профили без ключей/паролей; настоящий USB/usbmux-инвентарь |
| `get_status` | Mac doctor с подсказками или состояние iPhone root helper |
| `list_mac_apps`, `list_mac_windows` | Реальные приложения, PID и окна Mac |
| `get_ui_tree` | AX Mac либо единое дерево UIKit/SpringBoard/AssistiveTouch |
| `read_ui_tree`, `find_ui` | Страницы и локальный поиск по полному снимку |
| `act_ui` | Проверенное действие по узлу; автоматический semantic/HID/VNC |
| `get_screenshot` | PNG прямо в MCP-ответе, размеры и SHA-256 |
| `mac_input` | Focus, клики, drag, scroll, Unicode и клавиши с проверкой PID |
| `iphone_input` | Home/Lock, запуск приложения, текст и клавиатура |
| `iphone_gesture` | Настоящие HID-треки 1–5 пальцев, до 5 секунд |
| `iphone_system_control` | Переключатель приложений и Notification Center |
| `run_command` | Явный argv, коды выхода, таймауты; Mac user или iPhone root |
| `sync_source` | Инкрементальная передача без удаления удалённых файлов |
| `read_file` | Ограниченное чтение файлов и независимых результатов приложения |
| `run_workflow` | Существующие setup/build/install-команды плагина |

Всего 17 инструментов. Два MCP-ресурса: `openrevive://guide` и `openrevive://cli`.

Обычный цикл: `list_targets` → `get_ui_tree` → `find_ui` → `act_ui` → проверка нового дерева, изображения или независимого файла результата. Агент получает короткий `snapshotId`; полный JSON хранится в памяти сервера. Снимок привязан к сессии и устройству, действует 30 секунд и расходуется при первой попытке действия. Новый снимок того же устройства заменяет старый. Чтение страниц и поиск не продлевают срок.

## Устройство и установка

Сервер использует официальный TypeScript SDK MCP **2.3.1** и Zod **4.3.6**. Готовый `mcp/server.mjs` включает зависимости; при запуске не скачивается npm-пакет. Исходники, lockfile и лицензии входят в репозиторий. Пересборка:

```sh
npm ci --prefix tools/mcp --ignore-scripts
node tools/mcp/build.mjs
python3 tools/install.py --codex --claude
```

`mcp.json` регистрирует сервер для Codex, `.mcp.json` — для Claude Code. В Codex 0.137.0 подстановка `${PLUGIN_ROOT}` в `cwd` дала `No such file or directory`; совместимый запуск использует `cwd: "."` относительно плагина и `/bin/sh ./mcp/launch.sh`. Это проверено настоящим Codex app-server. Claude использует `${CLAUDE_PLUGIN_ROOT}`. Оба варианта запускают один и тот же сервер.

Для другого MCP-клиента достаточно:

```json
{
  "mcpServers": {
    "openrevive": {
      "command": "node",
      "args": ["/absolute/path/to/openrevive/mcp/server.mjs"],
      "env": {"OPENREVIVE_CONFIG": "/absolute/path/to/hosts.json"}
    }
  }
}
```

Аргументы сервера: `--host`, `--config`, `--python`; альтернативы — `OPENREVIVE_HOST`, `OPENREVIVE_CONFIG`, `OPENREVIVE_PYTHON`. По умолчанию используется профиль `blacklion` и существующий поиск конфигурации CLI. Настройки хоста и секреты остаются вне плагина. Для отдельной копии скилла MCP надо подключать отдельно; полная установка плагина подключает его автоматически.

## Поведение и границы

Python worker последовательно обслуживает операции и переиспользует SSH/USB-туннель. Одновременное обращение получает `busy`; межпроцессные UIKit/root leases сохранены. Длительный вызов не ставит клики в очередь. Выход клиента, EOF и отмена закрывают worker и принадлежащие ему локальные SSH/USB-процессы. Отмена не отменяет уже отправленный ввод; удалённая команда может завершаться до своего явного таймаута. После отмены старые ID недействительны, требуется новое наблюдение.

При остановившемся worker сервер переходит к принудительной очистке через 1.5 секунды, укладываясь в stdio grace клиента. Это проверено настоящим USB-сеансом: остановили только локальный Python-процесс через SIGSTOP, закрыли клиент, вся принадлежащая ему группа исчезла за 1.511 секунды. Сам iPhone при этом продолжал работать. Mac doctor возвращает полный структурированный отчёт с remedies даже при `ready: false`; ошибка соединения SSH остаётся ошибкой.

Сервер не открывает HTTP-порт. stdout содержит только MCP, ошибки идут через `isError` и stderr. Команды передаются аргументами без неявного shell. stdout/stderr команды ограничены 64 KiB каждый с явным `truncated`; общий текстовый ответ — 256 KiB, PNG — 8 MiB. Большой JSON из команды нельзя считать целым при `truncated: true`; для UI есть страницы и поиск по полному снимку.

На Mac перед coordinate/keyboard-вводом сервер будит дисплей: в Lion первый CGEvent на погасшем экране мог лишь разбудить его. AX-действия дополнительно перечитывают реальный узел и проверяют PID/start time, bundle, роль, заголовок и геометрию. `mac_input` проверяет ожидаемый foreground PID; точку выбирают по свежему снимку, а пересечение окон остаётся ответственностью вызывающего агента.

На iPhone сохраняются нативные проверки владельца, сессии, layout, foreground и системных окон. Раскрытый AssistiveTouch управляется по узлам через VNC; изображение по умолчанию берётся через native screenshotr, поскольку новый сеанс VNC может не показать меню. Жест требует свежего снимка, полного покрытия известных владельцев экрана и подходящего foreground; открытые внешние меню сначала закрывают через дерево. Произвольный canvas, web DOM, неизвестные overlay-процессы, landscape и другие модели/iOS не становятся автоматически поддержанными. `coverage` перечисляет пробелы; сервер не приписывает UI каждому kernel-процессу.

Подготовка отсутствующих возможностей описана в [MCP-справке](../plugins/openrevive/skills/legacy-mac/references/mcp.md), [настройке Mac](../plugins/openrevive/skills/legacy-mac/references/setup.md) и [настройке iPhone](../plugins/openrevive/skills/legacy-mac/references/iphone.md). В начале проверки iPhone был физически виден по USB при пустом mux-инвентаре; штатный `usb repair` восстановил соединение без перезагрузки телефона.

## Проверки

Итоговые команды и подтверждающие файлы перечислены в [evidence](mcp-evidence/README.md). Проверяются реальные BlackLion / OS X 10.7.5 / Xcode 4.6.3 и iPhone3,1 / iOS 6.1.3. MCP-клиент использует официальный SDK; дополнительно проверяется старое рукопожатие 2025-03-26 и завершение по EOF.

Источник формата и API: [OpenAI Plugins](https://developers.openai.com/plugins/build/plugins), [локальные stdio-серверы](https://developers.openai.com/plugins/deploy/desktop-only), [Claude Code plugins](https://code.claude.com/docs/en/plugins-reference), [официальный TypeScript SDK MCP](https://github.com/modelcontextprotocol/typescript-sdk). Версии клиентов и полученные ими каталоги сохраняются вместе с результатами аппаратной проверки.
