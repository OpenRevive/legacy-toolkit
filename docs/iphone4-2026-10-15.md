# iPhone 4: проверка и управление, 15 октября 2026

На физическом **oz.4 / iPhone 4 GSM / iPhone3,1 / iOS 6.1.3 (10B329) / armv7** через BlackLion удалось собрать и установить новое приложение OpenRevive, запустить его, удалённо заполнить форму, нажать кнопку и получить результат из файлов самого приложения. Канал: современный компьютер → Wi-Fi/SSH → MacBook с OS X 10.7.5/Xcode 4.6.3 → USB → iPhone. Во время проверки телефон заряжался; актуальная ёмкость на первом итоговом чтении — 35%.

## Что подтверждено

| Возможность | Проверка |
|---|---|
| Физический USB и рабочий mux | Один и тот же текущий UDID в hardware и usbmuxd; USB 0x05ac/0x1297 |
| Pairing | Pair → Validate → реальные DeviceName/ProductType/iOS/battery |
| Сборка и установка | Xcode iphoneos6.1, armv7, IPA; установщик завершил Install: Complete |
| Запуск | Собственный помощник вызывает SpringBoard; frontmostBundleId = org.openrevive.TouchProbe |
| Изображение экрана | Реальный screenshotr через developer image и отдельный RFB/Veency путь, 640×960 |
| Касания и ввод | Текст OpenRevive iPhone4 live → Apply; файл приложения содержит тот же текст, clicks = 2 |
| Системное управление | Settings → Home, Lock, пробуждение, свайп разблокировки; screenLocked меняется true → false |
| Команды и файлы | UID 0, чтение AFC2, вывод команд; exit 7 передаётся как 7, таймаут — 124 |

Первый независимый результат приложения:

```json
{"visibleResult":"Applied 2: OpenRevive iPhone4 live","clicks":2,"text":"OpenRevive iPhone4 live"}
```

## Что добавлено в OpenRevive 0.2.0

Команды `device --udid UDID pair|info|build-probe|install|prepare|launch|state|screenshot|tap|swipe|type|key|home|lock|exec|pull`, а также повторяемые `bootstrap-control` и `setup-vnc`. Каждая операция сама поднимает и закрывает свой SSH/USB-мост. Плагин и скилл остаются самостоятельными: личные профили, ключи, pairing-записи и VNC-пароль хранятся вне репозитория.

[Рабочая инструкция](../plugins/openrevive/skills/legacy-mac/references/iphone.md) содержит зависимости, команды, первичную настройку, восстановление и границы поддержки. [Скилл](../plugins/openrevive/skills/legacy-mac/SKILL.md) задаёт процесс для агента. [Зафиксированные пакеты](../plugins/openrevive/skills/legacy-mac/references/iphone-packages.json) загружаются из официальных репозиториев на современном компьютере с проверкой длины/SHA-256; бинарные пакеты и Apple developer images в Git не добавлены.

На телефоне уже были p0sixspwn 1.4-1, AppSync Unified 116.1, MobileSubstrate 0.9.6301 и AFC2. Для управления добавлены Veency 0.9.3500 и его зависимости: ldid, Screen Extension, AppList, HID Support, SpringBoardAccess, MouseSupport, libstatusbar. В Services.plist добавлена ровно одна запись `org.openrevive.exec`; исходная конфигурация сохранена. Собственный помощник находится в `/var/root/OpenRevive`. Его сервис ограничен USB и pairing; IP-службу для root-команд он не открывает. Veency также слушает сеть телефона и защищён отдельным случайным паролем, сохранённым приватно.

## Исправленные особенности старого окружения

- USB сначала видел iPhone, а зависший usbmuxd — нет. Перезапуск только `com.apple.usbmuxd` восстановил рабочий канал. Инвентарь теперь сравнивает оба слоя и понимает настоящий XML-формат Lion.
- Lion usbmuxd-296.4 не сохраняет pairing современным протоколом. Добавлено локальное приватное хранилище ReadBUID/ReadPairRecord/SavePairRecord/DeletePairRecord; сырой канал телефона проходит через SSH без изменения.
- После обычной перезагрузки понадобилось дождаться телефона и один раз пройти локскрин. Новый сервис lockdownd появился после этого; перезапуск всего телефона не нужен для обычных следующих команд.
- `idevicedebug` не смог получить task установленного AppSync-приложения. Собственный armv7-помощник с SpringBoard launch API успешно запустил его и прочитал активный bundle ID.
- LookupImage показывал false при реально смонтированном `/dev/disk1 on /Developer`. Повторное монтирование возвращало ImageMountFailed; syslog подтвердил, что /Developer уже занят. `prepare` теперь сначала проверяет настоящий screenshotr, затем при необходимости загружает образ из установленного Xcode.
- Из-за унаследованного SIGCHLD старый dpkg выдавал No child processes. Нативный помощник сбрасывает обработку сигналов и умеет завершать группу процессов по таймауту.
- В первом тесте ввод начался до фокуса поля; файл приложения остался пустым и проверка это обнаружила. Повтор с ожиданием и проверкой экрана дал правильный текст. Успех отправки события не считается успехом формы.

## Границы

Это практическое управление данным телефоном: изображение, однопальцевые жесты, клавиатура, кнопки, приложения, процессы и файловая система. Извлечение дерева произвольного UIKit-приложения, multitouch, симуляция датчиков и работа на stock iOS без подходящей подписи не проверены. Instruments UIAutomation на BlackLion остаётся отдельной нерешённой задачей. [Veency документирует](https://cydia.saurik.com/info/veency/) экран, ввод, Home и Lock; остальные утверждения в этом отчёте опираются на реальные проверки устройства.

## Итоговый аппаратный прогон

После обновления скилла тест заново собрал IPA, установил её, открыл приложение и ввёл новый nonce `OR-live-61f2ac2ac276`. Само приложение записало `clicks: 1` и тот же текст. VNC и screenshotr независимо показали одинаковый результат. Затем проверены переход в Settings, Home, Lock, пробуждение и разблокировка; системный lock state изменился false → true → false. Команда без pairing handshake получила отказ StartService -23, тогда как команды через установленную пару выполнялись с UID 0.

Проверки воспроизводятся командами:

```sh
python3 tests/check_iphone_protocol.py
python3 tests/check_iphone_live.py identity --udid АКТУАЛЬНЫЙ_UDID
python3 tests/check_iphone_live.py workflow --udid АКТУАЛЬНЫЙ_UDID
python3 tests/check_iphone_live.py control --udid АКТУАЛЬНЫЙ_UDID
python3 tests/check_package.py

```

Они требуют именно настроенный тестовый iPhone 4; workflow меняет только одноразовую форму OpenRevive, control проверяет системные кнопки и возвращает приложение. Сырые логи, IPA, developer image и приватные резервные копии остаются вне Git.

Итог: 7 из 7 проверок выполнены (6 автоматических и визуальная сверка). Установленные экземпляры Codex и Claude Code совпадают с исходниками 0.2.0; оба прочитали реальное состояние телефона из временного каталога вне проекта. Временные туннели закрыты.
